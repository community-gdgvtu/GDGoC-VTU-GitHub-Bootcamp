## Welcome, developer!

This is an interactive, beginner-friendly GitHub exercise created for the **Google Developer Groups on Campus — Visvesvaraya Technological University, Belagavi** bootcamp.

You will learn by completing four missions in this repository. A GitHub Actions workflow checks each milestone and posts the next lesson in your exercise issue.

### What you will learn

- What a repository, codebase, branch, commit, and pull request are.
- How to create a branch and safely work without changing `main`.
- How Markdown works and how to create a well-structured profile file.
- How to open, review, and merge a pull request.
- How GitHub Actions can automate a learning workflow.

### Your four missions

| Mission | Your task | What you learn |
|---|---|---|
| 1 | Create `my-first-branch` | Branches and safe parallel work |
| 2 | Create `PROFILE.md` and commit it | Files, Markdown, and commits |
| 3 | Open a pull request | Collaboration and code review |
| 4 | Merge your pull request | Integrating changes |

## Start the exercise

1. Click **Use this template** and create a **public** repository under your own GitHub account. Give it a name such as `my-github-bootcamp`.
2. Open the **Actions** tab in your new repository. If GitHub asks, click **I understand my workflows, go ahead and enable them**.
3. Wait for the **Step 0 — Start Exercise** workflow to finish. Refresh this README after it completes.
4. Open the issue titled **Exercise: GDGoC VTU GitHub Bootcamp — The First Contribution**. That issue is your personal lesson tracker. Follow its instructions in order.

> **Important:** Create your copy using **Use this template**, not Fork. Each participant needs their own repository so the exercise can track their own progress.

## GitHub concepts in two minutes

### What is a codebase?

A **codebase** is the collection of source code that makes up a software project. A project repository may also contain tests, documentation, images, configuration, and other files. Not every repository is an application codebase; some repositories primarily contain documentation or learning material.

### What is a repository?

A **repository** (repo) is a project space that stores files and tracks their change history with Git. A repository can contain one or many folders and files.

### What is Git?

**Git** is a distributed version-control system. It records changes as commits and helps developers work on separate branches, compare changes, and combine work.

### What is GitHub?

**GitHub** is an online platform for hosting Git repositories and collaborating through features such as pull requests, issues, discussions, projects, releases, and GitHub Actions.

### What is a README?

A **README** is the introduction to a repository. GitHub displays a repository's `README.md` prominently so visitors can understand what the project does, how to use it, and how to contribute.

### What is Markdown?

**Markdown** is a lightweight way to format plain text. Files ending in `.md` commonly use Markdown. You can write headings, lists, links, tables, images, and code blocks without writing HTML.

Example:

````markdown
# My project

A short description of what it does.

## Features

- Simple to use
- Open source

## Run it

```bash
python main.py
```
````

### What are the other common repository files?

| File or folder | Why it exists |
|---|---|
| `README.md` | Project overview and getting-started instructions |
| `LICENSE` | Terms under which others may use, modify, and distribute the project |
| `.gitignore` | Patterns for files Git should not track |
| `CONTRIBUTING.md` | How people should propose changes |
| `src/` | Often contains application source code |
| `tests/` | Often contains automated tests |
| `docs/` | Longer documentation |
| `.github/workflows/` | GitHub Actions workflow files |
